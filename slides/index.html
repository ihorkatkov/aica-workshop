What an agent is

A model in a loop. A tool call is structured text.

the conversation
userSchedule kickoff for D-104 today.
model · tool callget_record("D-104")
tool result{"security_review": "open"}
modelD-104's security review is still open…
  1. The conversation is text. All of it goes to the model.
  2. The model appends text. A tool call is text too.
  3. The harness executes the call. Not the model.
  4. The result is text too. Whoever writes the record writes into your prompt.

How do you know it works?

The vibe check

Install it, try it once, ship it. It breaks with many clients, or when the job is mission-critical.

Scenarios and evals

A scenario sends a real request to the real agent, then checks what was saved in the system and has a model judge the reply. An eval scores answers across many cases. Rerun both after every change.

Every change has to prove itself, even a simple one. And not only the prompt:

Challenge 1 · system validates

Enforce the kickoff rule at the write.

The rule

Kickoff needs a security review that is cleared and still valid on the CRM business date.

Otherwise reject, say why, and name what sales can do next. Urgency is not clearance.

Challenge 1 · one answer

A rejection the agent can act on.

def validate(record, action):
    if action != "schedule_kickoff":
        return None

    valid_until = record.get("review_valid_until")
    if (record.get("security_review") == "cleared"
            and valid_until
            and valid_until >= record["as_of"]):
        return None

    return {
        "code": "SECURITY_CLEARANCE_REQUIRED",
        "message": "Kickoff requires a security review…",
        "allowed": ["request_review_update"],
    }

Honest limits

What this lab does not do.

Approval re-checks only that the stage is unchanged since the proposal.
The policy is not re-run when the owner approves.
Approve applies immediately. There is no separate promote step.
Kickoff does not check the stage and is not idempotent. A retry records a second kickoff and can undo an owner's approval.
Identities are local demo identities. This is not production authorization.

Each one is a design question for your own system.
